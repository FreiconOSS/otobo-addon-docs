Rollen einrichten¶

Viele Klassen brauchen dieselben Angaben: Wer ist zuständig? Wo steht das Gerät? Wann wurde es gekauft, zu welchem Preis, auf welcher Kostenstelle? Statt diese Abschnitte in jede Klassendefinition zu kopieren, legt man sie einmal als Rolle an und bindet die Rolle in die Klassen ein.

Bemerkung

Eine CMDB-Rolle hat nichts mit den Rollen der Agentenverwaltung (Admin → Rollen) zu tun. Sie ist ein reiner Baustein für Klassendefinitionen und vergibt keine Rechte.

Das mitgelieferte Klassenpaket zeigt das Muster gut: Die Rolle ITSM Contact enthält den Abschnitt Kontakt und wird von zahlreichen Hardware-Klassen verwendet; die Rolle CMDB Located in bringt Standort und Adresse mit; für jede Klasse gibt es zusätzlich eine eigene Rolle ITSM GF <Klasse> mit den klassenspezifischen Feldern.

Eine Rolle anlegen¶

  1. Admin → General Catalog → Katalogklasse ITSM::ConfigItem::Role → Katalogeintrag hinzufügen. Name vergeben, z. B. Accounting.

    Die Katalogklasse erscheint erst, wenn es mindestens eine Rolle gibt. Ist sie noch nicht in der Liste, wird sie über Katalogklasse hinzufügen mit genau diesem Namen angelegt.

  2. Admin → Config Items → Rolle im Kasten Aktionen wählen → Rollendefinition ändern.

  3. Die Definition enthält nur Sections:

    ---
Sections:
  Accounting:
    Content:
      - Header: Beschaffung
      - DF: ITSMAccounting-InventoryNumber
      - DF: ITSMAccounting-CostUnit
      - DF: ITSMAccounting-DateOfInvoice
      - DF: ITSMAccounting-InvestmentCosts
  Warranty:
    Content:
      - Header: Garantie
      - DF: ITSMAccounting-WarrantyDate

    Es gelten dieselben Regeln wie für Abschnitte einer Klasse — siehe Klassendefinition (YAML). Pages wird in einer Rolle nicht ausgewertet, ebenso wenig ein Roles-Schlüssel: Rollen können keine weiteren Rollen enthalten.

Eine Rolle in einer Klasse verwenden¶

In der Klassendefinition wird die Rolle unter Roles mit einem frei gewählten Alias eingebunden. Ihre Abschnitte heißen danach <Alias>::<Abschnitt>:

---
Pages:
  - Name: Summary
    Content:
      - Section: Server
  - Name: Accounting
    Content:
      - Section: Buchhaltung::Accounting
      - Section: Buchhaltung::Warranty
Sections:
  Server:
    Content:
      - DF: Server-Hostname
Roles:
  Buchhaltung:
    Name: Accounting

Der Alias entkoppelt die Klasse vom Rollennamen: Wird eine Rolle später durch eine andere ersetzt, genügt es, Name zu ändern — die Verweise auf den Reitern bleiben gleich.

Rollen ändern — was passiert mit den Klassen?¶

Rollen werden beim Lesen in die Klassen eingemischt, nicht beim Speichern. Die Klassendefinition enthält nur den Verweis. Daraus folgt:

Ohne Version folgt die Klasse der Rolle.

Jede neue Rollenversion wirkt sofort in allen Klassen, die die Rolle ohne Version einbinden. OTOBO erzeugt dabei für jede dieser Klassen automatisch eine neue Definitionsversion, damit neue Felder der Rolle auch in den Config Items ankommen. Die Folgen für bestehende Config Items sind dieselben wie bei einer geänderten Klassendefinition (Versionen der Definition).

Mit Version bleibt die Klasse stehen.
Roles:
  Buchhaltung:
    Name: Accounting
    Version: 2

Die Klasse verwendet genau diese Rollenversion, bis Version geändert wird. Das eignet sich, wenn eine Rolle für neue Klassen umgebaut wird, bestehende Klassen aber vorerst unverändert bleiben sollen.

Warnung

Beim automatischen Nachziehen wird die Klassendefinition nicht erneut geprüft. Entfernt die neue Rollenversion zum Beispiel einen Abschnitt, den ein Reiter der Klasse verwendet, fällt das nirgends auf — der Abschnitt fehlt einfach in der Detailansicht. Nach größeren Rollenänderungen die betroffenen Klassen einmal im Editor öffnen und speichern: Dann zeigt die Prüfung eventuelle Fehler.

Warnung

Den Eintrag unter Roles immer als Zuordnung mit Name: schreiben. Die Kurzform ohne Wert (Buchhaltung: ~) wird zwar angezeigt, aber bei Rollenänderungen nicht nachgezogen — neue Felder der Rolle bleiben in solchen Klassen dann leer.

Eine Rolle ungültig zu setzen entfernt ihre Abschnitte ohne Meldung aus allen Klassen, die sie verwenden. Die Werte der Felder bleiben in der Datenbank erhalten.

Exportieren und importieren¶

Rollen werden wie Klassen exportiert und importiert (siehe Klassen exportieren und importieren). Der Eintrag in der Exportdatei trägt RoleName statt Class.

Warnung

Der Export einer Rolle enthält keine Felddefinitionen — die hängen an den Klassen. Rollen deshalb immer zusammen mit mindestens einer Klasse exportieren, die sie verwendet.
