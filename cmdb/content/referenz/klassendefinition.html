Klassendefinition (YAML)¶

Jede CMDB-Klasse wird durch eine Definition im YAML-Format beschrieben. Die Definition legt fest, welche Felder ein Config Item dieser Klasse hat, wie sie in Abschnitte gegliedert sind und auf welchen Reitern (Pages) der Detailansicht sie erscheinen. Bearbeitet wird sie unter Admin → Config Items → Klasse wählen → Klassen-Definition ändern.

Dieses Kapitel beschreibt alle Schlüssel, die OTOBO 11.0 auswertet. Wie man eine Klasse Schritt für Schritt aufbaut, zeigt Klassen einrichten.

OTOBO 11.1

Der Aufbau der Definition ist in 11.1 unverändert: kein Schlüssel kommt hinzu, keiner entfällt, die Prüfungen sind dieselben. Neu ist nur der Wert Public unter Interfaces (siehe Interfaces — Agent, Kunde, öffentlich).

Aufbau im Überblick¶

Eine Definition hat drei Ebenen auf oberster Stufe:

---
Pages:            Reiter der Detailansicht  (Pflicht)
  - Name            Reitername
    Interfaces      in welcher Oberfläche sichtbar
    Groups          nur für Mitglieder dieser Gruppen
    Layout          Spaltenraster des Reiters
    Content         welche Abschnitte wo stehen
      - Section       Name eines Abschnitts
        RowStart / RowSpan / ColumnStart / ColumnSpan
Sections:         Abschnitte mit Feldern  (Pflicht, darf aus Rollen stammen)
  <Name>:
    Type            DynamicFields | Description | ConfigItemLinks | ReferencedSection
    Content         Feldliste (bei DynamicFields)
      - Header        Zwischenüberschrift
      - DF            dynamisches Feld  (+ Label, Mandatory, Readonly)
      - Grid          mehrspaltiger Block
Roles:            wiederverwendbare Abschnitte einbinden  (optional)
  <Alias>:
    Name            Name der Rolle
    Version         feste Rollenversion (optional)

Die Trennung ist bewusst: Sections beschreiben was erfasst wird, Pages beschreiben wo es angezeigt wird. Ein Abschnitt kann auf mehreren Reitern erscheinen; ein Abschnitt, der auf keinem Reiter steht, ist in der Detailansicht unsichtbar, seine Felder gehören aber trotzdem zur Klasse.

Grundregeln¶

Die Definition muss mit --- beginnen — buchstäblich mit den ersten drei Zeichen. Eine Leerzeile oder ein Kommentar davor wird abgelehnt.

Unbekannte Schlüssel werden ignoriert, nicht gemeldet. Ein Tippfehler wie ColumSpan statt ColumnSpan besteht die Prüfung und bleibt einfach ohne Wirkung. Groß- und Kleinschreibung zählt überall.

Jede Textänderung erzeugt eine neue Version — auch eine geänderte Einrückung oder ein ergänzter Kommentar. Was eine neue Version für bestehende Config Items bedeutet, beschreibt Versionen der Definition.

Dynamische Felder müssen vorher existieren. Die Definition verweist nur auf Felder; angelegt werden sie unter Admin → Dynamische Felder mit dem Objekttyp ITSM ConfigElement (siehe Dynamische Felder für Config Items). Ein Feld, das nicht existiert oder ungültig gesetzt ist, lässt das Speichern scheitern.

Warnung

Ist der Text im Editor kein gültiges YAML, zeigt OTOBO beim Speichern eine leere Fehlerseite — und die Eingabe ist verloren. Größere Änderungen daher vorher in einem Texteditor sichern.

Die Fehlermeldungen der Prüfung erscheinen über dem Editor. Sie sind in OTOBO 11.0 größtenteils nicht übersetzt und werden deshalb auch in einer deutschen Oberfläche englisch angezeigt; eine Übersicht steht am Ende dieses Kapitels unter Fehlermeldungen beim Speichern.

Pages — die Reiter¶

Pages ist eine Liste. Jeder Eintrag erzeugt einen Reiter in der Detailansicht des Config Items. Die Reihenfolge der Liste ist die Reihenfolge der Reiter.

Name (Pflicht)

Beschriftung des Reiters. Sie wird über die Sprachdatei übersetzt, wenn eine Übersetzung existiert. Doppelte Namen werden nicht geprüft — vermeiden Sie sie, der Reiter ist über seinen Namen adressiert.

Content (Pflicht)

Liste der Abschnitte, die auf diesem Reiter stehen, mit ihrer Position im Raster. Darf nicht leer sein. Aufbau siehe Content — Abschnitte auf dem Reiter platzieren.

Layout (optional)

Spaltenraster des Reiters. Ohne Layout hat der Reiter eine Spalte.

Columns

Anzahl der Spalten (ganze Zahl). Standard: 1.

ColumnWidth

Breiten der Spalten, durch Leerzeichen getrennt, z. B. 1fr 2fr oder 300px 1fr. Fehlende Angaben werden mit 1fr aufgefüllt, überzählige verworfen.

Warnung

ColumnWidth versteht nur einfache Werte wie 1fr, 2.5fr, 200px, 12em oder auto. Prozentangaben, calc() und minmax() funktionieren nicht — aus 50% wird 50, und minmax(100px,1fr) zerfällt in drei Spalten.

Interfaces (optional)

In welchen Oberflächen der Reiter erscheint. Details unter Interfaces — Agent, Kunde, öffentlich.

Groups (optional)

Liste von Gruppennamen. Der Reiter ist nur für Benutzer sichtbar, die in mindestens einer dieser Gruppen sind. Details unter Groups — Reiter nur für bestimmte Gruppen.

Beispiel mit zwei Reitern:

---
Pages:
  - Name: Summary
    Layout:
      Columns: 2
      ColumnWidth: 1fr 1fr
    Interfaces:
      - Agent
      - Customer
    Content:
      - Section: General Information
        RowStart: 1
        ColumnStart: 1
      - Section: Description
        RowStart: 1
        ColumnStart: 2
  - Name: Accounting
    Groups:
      - itsm-accounting
    Content:
      - Section: Accounting

Interfaces — Agent, Kunde, öffentlich¶

Angabe

Wirkung

kein Interfaces

Reiter ist für Agenten sichtbar, für Kunden nicht.

Interfaces: [Agent]

nur Agenten

Interfaces: [Customer]

nur Kundenoberfläche

Interfaces: [Agent, Customer]

beide

Interfaces: []

Reiter ist nirgends sichtbar

Die Werte sind groß-/kleinschreibungsgenau: agent wirkt nicht.

Für die Kundenoberfläche genügt Customer allein nicht: Der Kunde muss das Config Item überhaupt sehen dürfen. Das regeln die Berechtigungsbedingungen, siehe Zugriff für Kunden.

OTOBO 11.1

Zusätzlich wertet OTOBO den Wert Public aus: Der Reiter erscheint in der öffentlichen CMDB-Ansicht (ohne Anmeldung). In 11.0 gilt das nur mit dem Zusatzpaket ITSMPublicCMDB; in 11.1 ist diese Funktion Teil der CMDB, aber ab Werk ausgeschaltet.

Groups — Reiter nur für bestimmte Gruppen¶

Groups steht ausschließlich auf Reiter-Ebene. Auf Abschnitts- oder Feldebene gibt es keinen Groups-Schlüssel — dort eingetragen, wird er ignoriert.

Pages:
  - Name: Lizenzkosten
    Groups:
      - itsm-accounting
      - admin
    Content:
      - Section: Accounting

Regeln:

  • Angegeben werden Gruppennamen, keine IDs.

  • Es genügt eine der Gruppen (ODER-Verknüpfung).

  • Agenten brauchen in der Gruppe mindestens das Recht ro; rw zählt ebenso. Gruppenmitgliedschaft über Rollen wird berücksichtigt.

  • In der Kundenoberfläche wird gegen die Kundengruppen geprüft (einschließlich der Gruppen der Kundenfirma). Ist CustomerGroupSupport ausgeschaltet — die Voreinstellung —, gilt die Bedingung für Kunden immer als erfüllt.

Groups wirkt auf Detailansicht, Bearbeiten-Maske, Suche und Druckansicht: Felder eines verborgenen Reiters werden dort weder angezeigt noch gespeichert, und in der Suche sind sie nicht als Suchkriterium verfügbar.

Warnung

Groups ist ein Anzeigefilter, kein Datenschutz. Die Sammelaktion (Bulk) zeigt die Felder aller Reiter, und über Import/Export und die Webservice-Schnittstelle sind alle Felder lesbar und schreibbar. Wer ein Config Item gar nicht sehen soll, wird über die Berechtigungsgruppe der Klasse ausgeschlossen (siehe Berechtigungen).

Content — Abschnitte auf dem Reiter platzieren¶

Jeder Eintrag in Pages[].Content setzt einen Abschnitt auf den Reiter.

Section (Pflicht)

Name des Abschnitts aus Sections. Stammt der Abschnitt aus einer Rolle, lautet der Name <Alias>::<Abschnitt> (siehe Roles — Abschnitte aus Rollen einbinden).

RowStart, RowSpan, ColumnStart, ColumnSpan (optional)

Position im Raster des Reiters: Startzeile, Anzahl überspannter Zeilen, Startspalte, Anzahl überspannter Spalten. Ohne Angabe verteilt der Browser die Abschnitte der Reihe nach auf das Raster.

Ein Beispiel für ein dreispaltiges Layout, in dem die Beschreibung rechts zwei Spalten und drei Zeilen einnimmt:

Layout:
  Columns: 3
  ColumnWidth: 1fr 1fr 1fr
Content:
  - Section: General Information
    RowStart: 1
    ColumnStart: 1
  - Section: Location
    RowStart: 2
    ColumnStart: 1
  - Section: Description
    RowStart: 1
    RowSpan: 3
    ColumnStart: 2
    ColumnSpan: 2

Bemerkung

Das Raster gilt für die Detailansicht. Die Bearbeiten-Maske ignoriert Layout und Positionen: Dort stehen die Abschnitte untereinander, bei mehr als einem Reiter in aufklappbaren Blöcken je Reiter. Ein Feld, das auf mehreren Reitern vorkommt, erscheint in der Maske nur einmal.

Sections — die Abschnitte¶

Sections ist eine Zuordnung Name → Abschnitt. Der Name ist frei wählbar und wird in Pages[].Content[].Section referenziert. Über Type wird die Art des Abschnitts bestimmt:

Type

Inhalt

Wo wirksam

(ohne) oder DynamicFields

Liste dynamischer Felder, Überschriften und Raster

Detail, Bearbeiten, Suche, Druck

Description

Beschreibungstext (Rich Text) des Config Items

Detail, Bearbeiten, Druck, Import/Export

ConfigItemLinks

Verknüpfte Config Items, nach Klasse gruppiert

Detail, Druck

ReferencedSection

Abschnitt eines referenzierten Config Items

nur Detail

Andere Werte für Type werden mit Invalid type in section … abgelehnt.

Abschnitt mit dynamischen Feldern¶

Der Normalfall. Content ist eine Liste; jedes Element enthält genau einen der Schlüssel Header, DF oder Grid.

Sections:
  General Information:
    Content:
      - Header: Allgemein
      - DF: ITSM-SerialNumber
      - DF: ITSM-Vendor
        Mandatory: 1
      - DF: ITSM-WarrantyExpiration
        Label: Garantie bis
      - DF: ITSM-LensToContractType
        Readonly: 1
Header

Zwischenüberschrift. In der Detailansicht erzeugt jeder Header eine Überschrift an seiner Stelle. In der Bearbeiten-Maske wird nur der erste Header eines Abschnitts verwendet — als Überschrift über dem ganzen Abschnitt.

DF

Name eines dynamischen Feldes mit Objekttyp ITSM ConfigElement. Ergänzende Schlüssel am selben Listeneintrag:

Label

Überschreibt die Feldbeschriftung — in Detailansicht und Bearbeiten-Maske. So kann dasselbe Feld in zwei Klassen unterschiedlich heißen.

Mandatory: 1

Pflichtfeld in der Bearbeiten-Maske.

Warnung

Die Pflichtprüfung findet nur im Browser statt. Beim Anlegen über Import/Export oder Webservice, und bei der Sammelaktion, wird sie nicht erzwungen.

Readonly: 1

Das Feld wird in der Bearbeiten-Maske angezeigt, aber nicht bearbeitbar; ein übermittelter Wert wird ignoriert. Typisch für Lens- und Skript-Felder, deren Wert sich aus anderen Feldern ergibt.

Grid

Mehrspaltiger Block innerhalb eines Abschnitts.

Columns (praktisch Pflicht)

Anzahl Spalten, ganze Zahl größer 0.

ColumnWidth

Spaltenbreiten, gleiche Regeln wie bei Layout.

Rows (Pflicht)

Liste von Zeilen; jede Zeile ist eine Liste von Zellen. Jede Zelle braucht DF und kann Label, Mandatory, Readonly, ColumnStart und ColumnSpan haben.

- Grid:
    Columns: 3
    ColumnWidth: 2fr 1fr 1fr
    Rows:
      - - DF: ITSM-CPU
        - DF: ITSM-CPUCores
        - DF: ITSM-CPUThreads
      - - DF: ITSM-RAM
          ColumnSpan: 3

Warnung

Die Prüfung beim Speichern verlangt Columns nicht. Fehlt es oder ist es keine ganze Zahl größer 0, lässt die Bearbeiten-Maske das komplette Raster weg — die Felder sind dann nicht mehr bearbeitbar. Columns daher immer setzen.

ColumnStart und ColumnSpan in Zellen wirken nur in der Bearbeiten-Maske; die Detailansicht setzt die Zellen der Reihe nach.

Abschnitt Description¶

Zeigt den Beschreibungstext des Config Items (Rich Text mit Bildern). Weitere Schlüssel gibt es nicht; ein Header wird ignoriert, die Überschrift lautet immer Beschreibung.

Sections:
  Description:
    Type: Description

Die Existenz dieses Abschnitts schaltet das Beschreibungsfeld ein: Nur wenn eine Klasse einen Description-Abschnitt auf einem Agenten-Reiter hat, bietet die Bearbeiten-Maske das Feld an, druckt die Druckansicht die Beschreibung und kennt Import/Export das Attribut.

Abschnitt ConfigItemLinks¶

Listet die über Verknüpfen mit diesem Config Item verbundenen Config Items auf, gruppiert nach Klasse.

Sections:
  Backlinks:
    Type: ConfigItemLinks
    Header: Verwendet von
    LinkedAs: Target
    LinkTypes:
      - DependsOn
Header (optional)

Überschrift des Abschnitts.

LinkedAs (optional, Standard Source )

Richtung der Verknüpfung aus Sicht dieses Config Items:

  • Source — Config Items, auf die dieses zeigt (dieses ist Quelle),

  • Target — Config Items, die auf dieses zeigen (dieses ist Ziel),

  • jeder andere Wert — beide Richtungen.

LinkTypes (optional)

Liste von Linktyp-Namen (z. B. DependsOn, Includes, RelevantTo; siehe Verknüpfungen und Vorfallstatus-Vererbung). Ohne Angabe oder bei leerer Liste werden alle Linktypen gezeigt.

Bemerkung

Der Abschnitt prüft keine Berechtigungen auf die verknüpften Config Items: Deren Name ist für jeden sichtbar, der das aktuelle Config Item sieht — auch in der Kundenoberfläche, wenn der Reiter dort freigegeben ist.

Abschnitt ReferencedSection¶

Zeigt einen Abschnitt eines anderen Config Items an, auf das ein Referenzfeld zeigt. Damit lässt sich zum Beispiel beim Arbeitsplatzrechner die Adresse des Standorts einblenden, ohne sie doppelt zu pflegen.

Sections:
  Address:
    Type: ReferencedSection
    ReferenceField: Location-ReferenceToLocation
    SectionName: Address
    FieldListPre:
      - DF: Location-ReferenceToLocation
        Label: Standort
    FieldListPost:
      - DF: Location-Room
ReferenceField

Referenzfeld dieses Config Items vom Typ Config Item oder Config Item Version.

SectionName

Name des Abschnitts in der Definition des referenzierten Config Items (bei Rollen-Abschnitten dort mit <Alias>::).

FieldListPre, FieldListPost (optional)

Felder dieses Config Items, die vor bzw. nach dem fremden Abschnitt angezeigt werden; Einträge wie {DF, Label}.

Verweist das Referenzfeld auf mehrere Config Items, wird das erste verwendet. Ketten funktionieren: Ein Raum zeigt das Gebäude, das Gebäude den Standort.

Warnung

Die Schlüssel von ReferencedSection werden beim Speichern nicht geprüft. Ein falscher SectionName fällt erst in der Detailansicht auf, wo der Abschnitt einfach leer bleibt. Auch hier gibt es keine Berechtigungsprüfung auf das referenzierte Config Item.

ReferencedSection wirkt nur in der Detailansicht; Bearbeiten-Maske, Suche und Druck überspringen den Abschnitt.

Roles — Abschnitte aus Rollen einbinden¶

Eine Rolle ist eine Definition, die nur aus Sections besteht. Klassen binden sie ein und können deren Abschnitte dann auf ihren Reitern verwenden. So wird zum Beispiel ein Abschnitt Kontakt einmal gepflegt und von zehn Klassen genutzt. Anlegen und Pflegen von Rollen beschreibt Rollen einrichten.

---
Pages:
  - Name: Summary
    Content:
      - Section: General Fields::General Information
      - Section: Contact::Contact
Roles:
  General Fields:
    Name: ITSM GF Computer
  Contact:
    Name: ITSM Contact
    Version: 3
<Alias>

Frei gewählter Schlüssel unter Roles. Alle Abschnitte der Rolle werden als <Alias>::<Abschnittsname> in die Klasse übernommen. Referenziert wird über den Alias, nicht über den Rollennamen.

Name (optional)

Name der Rolle, wie er im General Catalog steht. Fehlt Name, gilt der Alias als Rollenname.

Version (optional)

Bindet eine bestimmte Rollenversion. Ohne Version wird immer die neueste Version verwendet.

Regeln:

  • Ein Rollenabschnitt überschreibt einen gleichnamigen Abschnitt der Klasse.

  • Alle Abschnitte der Rolle gehören zur Klasse — auch solche, die auf keinem Reiter stehen. Ihre Felder werden damit Teil der Klasse (Import/Export, Webservice).

  • Rollen können keine weiteren Rollen einbinden; ein Roles-Schlüssel in einer Rollendefinition bleibt ohne Wirkung.

  • Nur gültige Rollen werden gefunden.

Warnung

Den Eintrag unter Roles immer als Zuordnung schreiben, also mit Name: darunter — nicht leer (Contact: ~). Die leere Form wird zwar angezeigt, aber bei einer Änderung der Rolle nicht mitaktualisiert: Neue Felder der Rolle bleiben in der Klasse dann leer.

Warnung

Wird eine Rolle ungültig gesetzt oder umbenannt, verschwinden ihre Abschnitte stillschweigend aus allen Klassen, die sie verwenden. Eine Fehlermeldung gibt es erst beim nächsten Speichern der Klassendefinition.

Vollständiges Beispiel¶

Eine Klasse Server mit zwei Reitern, einer Rolle, einem Raster, verknüpften Config Items und einem eingeblendeten Standort:

---
Pages:
  - Name: Summary
    Layout:
      Columns: 2
      ColumnWidth: 3fr 2fr
    Interfaces:
      - Agent
      - Customer
    Content:
      - Section: Server
        RowStart: 1
        ColumnStart: 1
      - Section: Contact::Contact
        RowStart: 1
        ColumnStart: 2
      - Section: Address
        RowStart: 2
        ColumnStart: 2
      - Section: Description
        RowStart: 2
        ColumnStart: 1
  - Name: Hardware
    Content:
      - Section: Hardware
  - Name: Dependencies
    Content:
      - Section: Depends on
      - Section: Used by

Sections:
  Server:
    Content:
      - Header: Server
      - DF: Server-Hostname
        Mandatory: 1
      - DF: Server-OperatingSystem
      - DF: Location-ReferenceToLocation
        Label: Standort
  Hardware:
    Content:
      - Header: Hardware
      - Grid:
          Columns: 2
          Rows:
            - - DF: Server-CPU
              - DF: Server-RAM
            - - DF: Server-Disk
                ColumnSpan: 2
  Description:
    Type: Description
  Address:
    Type: ReferencedSection
    ReferenceField: Location-ReferenceToLocation
    SectionName: Address
  Depends on:
    Type: ConfigItemLinks
    Header: Hängt ab von
    LinkedAs: Source
    LinkTypes:
      - DependsOn
  Used by:
    Type: ConfigItemLinks
    Header: Wird verwendet von
    LinkedAs: Target

Roles:
  Contact:
    Name: ITSM Contact
