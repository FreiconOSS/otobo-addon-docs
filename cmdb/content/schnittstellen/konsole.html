Konsolenbefehle¶

Alle Befehle werden als OTOBO-Benutzer im Installationsverzeichnis aufgerufen:

bin/otobo.Console.pl <Befehl> [Optionen]

bin/otobo.Console.pl <Befehl> --help zeigt die Optionen eines Befehls. Die Befehle laufen mit Administratorrechten; die Berechtigungsgruppen der Klassen spielen hier keine Rolle.

OTOBO 11.1

In 11.1 kommt kein Befehl hinzu und keiner entfällt. UpgradeTo11 schreibt neue Feld-Namensräume dort in Namespaces###DynamicField.

Klassen¶

Admin::ITSM::ConfigItem::ClassExport

Exportiert Klassen und Rollen samt Definition und Feldern als YAML (Format siehe Klassen exportieren und importieren).

--class <Name>

Klasse oder Rolle; mehrfach angebbar. Pflicht.

--file <Datei>

Zieldatei. Standard: <erste Klasse>.yml.

--force

Vorhandene Datei überschreiben.

Admin::ITSM::ConfigItem::ClassImport

Importiert eine Klassendatei.

--file <Datei>

Pflicht.

--update

Vorhandene Klassen und Rollen aktualisieren. Ohne diese Option bricht der Import ab, wenn ein Name schon existiert.

Admin::ITSM::ConfigItem::UpgradeTo11

Migriert CMDB-Daten aus OTOBO 10 auf das Feldmodell von 11.0. Ablauf und Hinweise siehe Klassen einrichten.

--use-defaults

Ohne Rückfragen.

--start-at <0–4>

Mit Schritt 0 (Zuordnung vorbereiten), 1 (Definitionen vorbereiten), 2 (Definitionen migrieren), 3 (Werte migrieren) oder 4 (Altdaten löschen) beginnen.

--tmpdir <Verzeichnis>

Arbeitsverzeichnis für die Zwischendateien.

--no-namespace <Attribut,Attribut>

Alte Attribute, deren neue Felder ohne Namensraum-Präfix angelegt werden.

Admin::ITSM::ConfigItem::ConvertLegacyRefDFs

Stellt Referenzfelder des OTOBO-10-Zusatzpakets ITSMConfigItemReference auf Standard-Referenzfelder vom Typ Config Item um.

--file <Datei>

Bericht in eine Datei statt auf den Bildschirm.

--force

Ohne Rückfrage.

Config Items¶

Admin::ITSM::ConfigItem::Delete

Löscht Config Items oder alte Versionen. Endgültig, einschließlich Historie.

--all

Alle Config Items löschen. Mit dem Argument y ohne Rückfrage.

--class <Name>

Alle Config Items einer Klasse.

--deployment-state <Name>

Nur zusammen mit --class: nur Config Items in diesem Verwendungsstatus.

--configitem-number <Nummer>

Bestimmte Config Items; mehrfach angebbar. Nicht mit --class kombinierbar.

--all-old-versions

Bei allen Config Items nur die neueste Version behalten.

--all-but-keep-last-versions <N>

Bei allen Config Items die neuesten N Versionen behalten.

--all-older-than-days-versions <N>

Versionen löschen, die älter als N Tage sind — mindestens eine Version bleibt immer erhalten.

Die --all…-Optionen schließen einander und alle übrigen Optionen aus.

# Versionsgeschichte auf die letzten 10 Versionen je Config Item kürzen
bin/otobo.Console.pl Admin::ITSM::ConfigItem::Delete --all-but-keep-last-versions 10
Admin::ITSM::ConfigItem::ListDuplicates

Listet Config Items mit gleichem Namen — nützlich, bevor die Namensprüfung (UniqueCIName::EnableUniquenessCheck) eingeschaltet wird.

--class <Name>

Nur diese Klasse.

--scope global|class

Doppelt über alle Klassen oder innerhalb einer Klasse. Standard: Wert von UniqueCIName::UniquenessCheckScope.

--all-states

Auch Config Items in postproductive Verwendungsstatus einbeziehen (sonst nur vorproduktive und produktive).

Wartung¶

Admin::ITSM::IncidentState::Recalculate

Berechnet den aktuellen Vorfallstatus neu — nötig nach einer Änderung von ITSM::Core::IncidentLinkTypeDirection (siehe Verknüpfungen und Vorfallstatus-Vererbung). Setzt anschließend den aus Config Items abgeleiteten Status der Services zurück, sodass er neu ermittelt wird.

--configitem-number <Nummer>

Nur diese Config Items; mehrfach angebbar. Ohne Angabe: alle.

Maint::ITSM::ConfigItem::RebuildLinkTable

Baut die interne Beziehungstabelle der CMDB neu auf: aus allen Referenzfeldern mit Linktyp und aus den von Hand angelegten Verknüpfungen zwischen Config Items. Sie ist die Grundlage von Baumansicht, ConfigItemLinks-Abschnitten und Vorfallvererbung. Keine Optionen.

Warnung

Der Befehl leert die Tabelle zuerst. Gibt es kein einziges Referenzfeld vom Typ Config Item mit hinterlegtem Linktyp, bricht er danach mit No relevant dynamic fields were found ab — die von Hand angelegten Verknüpfungen zwischen Config Items werden dann nicht wieder eingetragen und fehlen in Baumansicht und Vorfallvererbung. Auf Systemen ohne solche Referenzfelder den Befehl nicht ausführen.

Maint::ITSM::ConfigItem::CreateConditionalTickets

Erzeugt Tickets nach den Regeln CMDBNotifications::Rules###… — etwa, wenn ein Vertrag oder Zertifikat abläuft (siehe Verknüpfungen und Vorfallstatus-Vererbung). Läuft normalerweise über den Daemon-Task Daemon::SchedulerCronTaskManager::Task###CMDBNotifications. Keine Optionen.

Admin::ITSM::ConfigItem::DumpGraph

Schreibt alle Beziehungen zwischen Config Items als Grafik OTOBO_ITSM_Config_Items.svg ins aktuelle Verzeichnis. Benötigt das Perl-Modul GraphViz2. Keine Optionen.

Import/Export¶

Admin::ImportExport::Import

Führt eine Import-Vorlage aus (siehe Import und Export von Config Items).

--template-number <N>

Nummer der Vorlage. Pflicht.

--prefix <Präfix>

Ist die Quelle ein Verzeichnis: Dateien <Präfix>NNNNNN.csv einlesen.

<Quelle>

Datei oder Verzeichnis.

Admin::ImportExport::Export

Führt eine Export-Vorlage aus.

--template-number <N>

Nummer der Vorlage. Pflicht.

<Ziel>

Zieldatei.

Admin::ITSM::ImportExport::Import, Admin::ITSM::ImportExport::Export

Ältere Fassungen aus dem CMDB-Paket mit nur --template-number und Datei. Stattdessen die Befehle Admin::ImportExport::… verwenden.

Webservice¶

Maint::WebService::TriggerConfigItemFetch

Führt einen ConfigItemFetch-Invoker sofort aus (siehe Webservice (Generic Interface)).

<Webservice>

Name des Webservices; er muss gültig sein.

<Invoker>

Name des Invokers; er braucht im Webservice eine REST-Zuordnung.
