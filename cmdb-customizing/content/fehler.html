Wenn etwas nicht stimmt¶

Klassenwechsel¶

Die Maske nennt den Grund selbst, das Systemprotokoll ergänzt die Einzelheiten.

Meldung

Ursache und Abhilfe

Der Name … ist in der Klasse … schon vergeben.

UniqueCIName::EnableUniquenessCheck ist aktiv, und die neue Klasse hat bereits ein Config Item mit diesem Namen. Benennen Sie eines davon um.

Das Feld … kann den Wert von … nicht aufnehmen.

Die Zuordnung passt nicht mehr zu dem, was die Maske angeboten hat. Das Config Item wurde zwischendurch geändert. Öffnen Sie die Maske erneut.

Für das Feld … ein Config Item wählen.

Ein Feld unter Neue Referenz wählen wurde ohne Config Item abgeschickt. Die Maske sperrt dafür den Knopf, ihr Skript lief also nicht. Öffnen Sie die Maske erneut.

Das Config Item … kann für das Feld … nicht gewählt werden.

Es hat eine Klasse, die das Feld nicht erlaubt, existiert nicht mehr oder ist das Config Item selbst. Es wurde nichts geändert. Wählen Sie ein anderes.

Das Feld … nimmt nur einen Wert auf.

Für ein Feld mit einem Wert kamen mehrere Config Items an. Es wurde nichts geändert. Entfernen Sie alle bis auf eines.

Die neue Version konnte nicht angelegt werden, die Klasse ist unverändert.

OTOBO hat die neue Version abgelehnt, die Protokollzeilen davor nennen den Grund, etwa ein nicht ladbares Namensmodul. Klasse und aktuelle Version sind zurückgesetzt.

Die Werte … konnten nicht gespeichert werden, die Klasse ist unverändert.

Die genannten Felder waren in der neuen Version leer. Die Version wurde wieder entfernt und die Klasse zurückgesetzt.

Die Klasse konnte nicht geändert werden.

Das Schreiben in die Datenbank schlug fehl, siehe Protokoll. Es wurde nichts geändert.

Der Klassenwechsel konnte nicht vorbereitet werden.

Die Zielklasse hat keine Definition oder ist ungültig, oder das Config Item hat keine Version.

Es gibt keine andere Klasse, in die Sie schreiben dürfen.

Es fehlt das Schreibrecht (rw) auf jede andere Klasse.

Im Protokoll können außerdem stehen:

CIClassChange: config item … into class … failed (…), set back to class ….

Der Wechsel schlug fehl und wurde zurückgenommen. Der Text in Klammern nennt den Grund. died: bedeutet, dass OTOBO oder ein Ereignis-Modul beim Anlegen der Version abgebrochen hat.

CIClassChange: config item … could not be set back to class … - check it by hand.

Auch das Zurücksetzen schlug fehl. Prüfen Sie Klasse und aktuelle Version des Config Items in der Datenbank.

CIClassChange: the mapping from class … to … could not be remembered.

Die Klasse wurde geändert, nur das Merken der Zuordnung schlug fehl. Es ist nichts rückgängig zu machen, setzen Sie den Haken beim nächsten Mal erneut.

CIClassChange: the links of field … of config item … could not be removed.

Der alte Feld-Bezug ließ sich nicht entfernen. Die Klasse ist bereits gewechselt. Prüfen Sie die Verknüpfungen des Config Items.

CIClassChange: config item … could not keep its relation to … (field …) as a link.

Eine Beziehung konnte nicht als Verknüpfung erhalten werden. Die Klasse ist bereits gewechselt, der alte Wert steht in der vorherigen Version. Legen Sie die Verknüpfung von Hand an.

CIClassChange: link type … is not possible between config items, the relations of field … stay in the history only.

(Hinweis) Der Verknüpfungstyp des Feldes ist zwischen Config Items nicht erlaubt. Die Beziehung bleibt nur in der Historie.

Das Zurücksetzen entfernt die neue Version und stellt das Config Item wieder her, aber nicht das, was geschah, solange die Version bestand: ihre Historieneinträge, Verknüpfungen, die OTOBO für ein übertragenes Referenzfeld angelegt hat, und was Ereignis-Module auf VersionCreate oder ConfigItemDynamicFieldUpdate_* getan haben.

Die Suche unter Neue Referenz wählen und die Prüfung beim Absenden laufen auseinander

Die Suche nutzt das Feld, wie es jetzt konfiguriert ist, die Prüfung die Kopie in der Klassendefinition. Wurde die Einschränkung eines Feldes geändert und die Definition nicht neu gespeichert, kann die Suche ein Config Item anbieten, das dann abgelehnt wird, oder eines nicht finden, das passen würde. Speichern Sie die Klassendefinition erneut.

Tiefe Linse bleibt leer¶

Nutzen Sie zuerst Kette prüfen im Dialog des Feldes. Es sagt je Objekt, wo die Kette endet. Hat eine Klasse unterwegs das nächste Feld nicht, meldet das Protokoll dies einmal je Aufruf. Eine leere Referenz unterwegs sind normale Daten und werden nicht protokolliert.

PathResolver: path '…' cannot resolve — config item … (version …) is of class '…', which does not carry the field '…' (it exists on: …). The chain is configured for a different class.

Die Referenz zeigt auf eine Klasse, für die die Kette nicht gewählt wurde. Beschränken Sie das Referenzfeld auf eine Klasse oder legen Sie für die andere Klasse eine zweite Linse an.

PathResolver: dynamic field '…' does not exist, path broken.

Ein Feld des Pfades wurde nach dem Speichern gelöscht oder umbenannt. Öffnen Sie die Linse und wählen Sie die Kette neu.

DeepLense '…': no config item for version ID '…'.

Das verwiesene Config Item wurde gelöscht.

DynamicField DeepLense '…' is not supported inside a set.

Die Linse liegt in einem Set, das wird nicht unterstützt.

DynamicField DeepLense '…' ends on the native attribute '…', which cannot be written; the submitted value was discarded.

(Hinweis) Die Linse endet auf einem Attribut wie @Number und stand in einer Bearbeitungsmaske. Es gibt kein Feld, in das geschrieben werden könnte.

Das Speichern einer Tiefen Linse wird abgelehnt, wenn ein Abschnitt kein Referenzfeld ist, ein Feld nicht existiert, der Pfad länger als DeepLenseMaxDepth ist oder der Pfad auf einer anderen Linse endet. Der Dialog nennt den Grund.

CI Connector¶

Need TicketID in Data! oder Need …! im Protokoll bedeuten, dass das Ereignis oder der Aufruf ohne die nötigen Daten ausgelöst wurde. Meist entfernt ein angepasstes Template die versteckten Felder des Widgets.

CSV-Import endet mit einem internen Serverfehler¶

Im Protokoll steht Can't use string ("…") as an ARRAY ref in BaseEntity.pm. Dieses Paket behebt den Fehler für einwertige Referenzfelder mit einem Import-Suchattribut. Bleibt das Feld danach beim Import leer, findet das Suchattribut zu dem Wert kein Config Item. Enthält die CSV-Datei Config-Item-IDs, lassen Sie das Suchattribut leer.

Altes Paket DynamicFieldDeepLense noch installiert¶

Die Tiefe Linse war früher ein eigenes Paket. Vier Dateien liegen in beiden unter demselben Pfad, die Installation kollidiert also. Deinstallieren Sie DynamicFieldDeepLense zuerst. Eingerichtete Felder bleiben erhalten, der Feldtyp behält seinen Namen.
